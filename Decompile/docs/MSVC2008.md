# Running Visual C++ 2008 on Apple silicon

The game was built with Visual C++ 2008 (VC9). Byte-exact matching needs that
compiler, not clang and not a newer MSVC. This is how it runs here.

## What runs

```text
macOS arm64 (Apple silicon)
  └─ OrbStack -> linux/386 Debian bookworm container (QEMU TCG)
       └─ Wine 8 (win32 prefix)
            └─ cl.exe 15.00.30729.01 (SP1) or 15.00.21022.08 (original)
                 ├─ Windows SDK 6.0A headers/libs
                 └─ VC9 CRT msvcr90/msvcp90 beside cl.exe
```

Verified versions:

| Flavor | Command | Version |
| --- | --- | --- |
| SP1 | `Decompile/tools/msvc/cl.sh` | `15.00.30729.01` |
| original | `SMR_MSVC_FLAVOR=rtm Decompile/tools/msvc/cl.sh` | `15.00.21022.08` |

## Setup

One command, from the repository root:

```sh
./Decompile/tools/msvc/setup.sh
```

It:

1. downloads Microsoft's official ISO images into
   `work/inputs/toolchains/` (749 MB + 894 MB),
2. builds the `smr-msvc9` image from
   [`tools/msvc/Dockerfile`](../tools/msvc/Dockerfile),
3. extracts `VCExpress/Ixpvc.exe` -> `vs_setup.msi` -> `VC/` and the Windows
   SDK,
4. installs both flavours under `work/toolchains/msvc9/{sp1,rtm}`.

Nothing in the repository redistributes Microsoft's files. The ISOs are
downloaded from `download.microsoft.com` and remain subject to Microsoft's
licence.

Use `./Decompile/tools/msvc/setup.sh sp1` or `... rtm` to fetch one flavour.
Re-running is safe; finished flavours are skipped.

## Compile

`cl.sh` passes its arguments to `cl.exe`, sets `INCLUDE`/`LIB` to the VC9 and
SDK paths, and mounts the repository at `/work`:

```sh
cd work/toolchains/msvc-test
../../../Decompile/tools/msvc/cl.sh /nologo /c /TC /O2 /Fotest.obj test.c
```

Environment variables:

| Variable | Meaning |
| --- | --- |
| `SMR_MSVC_HOME` | toolchain root (default `work/toolchains/msvc9`) |
| `SMR_MSVC_FLAVOR` | `sp1` (default) or `rtm` |
| `SMR_MSVC_IMAGE` | Docker image (default `smr-msvc9`) |

The first run creates a 32-bit Wine prefix at
`work/toolchains/msvc9/wine/`. It is reused afterwards.

## Verify matches

All verified functions live in `src/matched/` and are registered in
[`config/matched.json`](../config/matched.json). The check compiles each
source once and compares every registered function at its original address:

```sh
python3 Decompile/tools/match/verify.py
```

Current output:

```text
196/196 matched, 1,547 bytes; 0 mismatch, 0 missing, 0 unresolved reloc
compiler: msvc9-sp1 15.00.30729.01
```

The registry contains 149 tail-call thunks, 19 field accessors, one real
function with two relocations (`rand() * 2^-15`), and 23 C++/C functions in
`bank_0088` (constructors, copy methods, setters, wrappers). The thunks are ABI
passthroughs and are marked `kind: tail_thunk`; their C signatures are
deliberately `void(void)`. `bank_0088` is at **34/250 functions, 657 bytes**.

## Notes and traps

- **Do not use `xvfb-run` around `cl.exe`.** The compiler is console-only and
  works headless. In this environment `xvfb-run` starts Xvfb and then hangs
  before launching Wine.
- **OrbStack must be running.** `docker info` should report a Linux context
  (`orbstack`). If not: `open -a OrbStack`, then `docker info`.
- **A killed command can leave a container alive.** Check `docker ps`; remove
  a stuck one with `docker rm -f <id>`. A container still holding
  `work/toolchains/msvc9/wine` makes the next run look hung.
- **Linux/386 runs under QEMU TCG** here, so compiler startup is slower than
  native. Batch functions into units; do not start a container per function.
- **The Wine prefix is persistent.** If it ever becomes inconsistent, delete
  `work/toolchains/msvc9/wine`; `cl.sh` recreates it.
- **Flags are per unit.** The first matches use `/O2 /TC`. Real units will need
  the original optimisation, SEH and language flags inferred from the binary;
  never assume `/O2` everywhere.
- **Relocations are not yet compared symbolically.** `verify.py` masks
  relocation spans unless `--strict-relocs` is used; see
  [MATCHING.md](MATCHING.md).
